# 记忆系统实施任务 Plan

日期：2026-08-21
设计依据：docs/2026-08-20-memory-system-design.zh.md（定稿）
规则：完成一个勾一个；每个任务附验收标准。

## 阶段一：骨架（引擎在宿主里跑起来）

- [ ] **T1 vendor 落地**：复制腾讯 MemoryCore 的 `src/core` + `src/adapters/standalone` + `src/utils` + `src/config.ts` 进 `dsh-harness/bundle/memory/vendor/`，裁掉 gateway/openclaw 壳/云后端/计费观测，清理失效 import，版权头保留。tsc 编译通过。验收：vendor 目录独立编译绿。
- [ ] **T2 bundle 骨架**：`dsh-harness/bundle/memory/` 标准形态——package.json（dsh.bundle 声明）、tsconfig、tsdown、cordis.patch.yml、host apply 入口。验收：tsc -b + tsdown 全量重建过。
- [ ] **T3 适配层**：HostAdapter 实现（数据目录 `~/.dsh/memory/`、日志、配置注入）+ LLMRunner 实现（`run` → `ctx.llm.stream`，提炼走模型方案）。验收：单测覆盖两个适配器。
- [ ] **T4 上架存活**：patch 行进 profile、reconcile、重启后引擎初始化成功（存活但不做任何事）。验收：--dump-config 含 memory 行；启动日志无错；`~/.dsh/memory/` 目录建成。

## 阶段二：数据与提炼

- [ ] **T5 触发接线**：DSH 会话每轮结束 → `handleTurnCommitted`（归属坐标：团队/角色/任务/会话自动推导，主会话=team 维度）。验收：发消息后引擎 L0 有记录。
- [ ] **T6 三维归属**：team / team+role / project 三 scope 并行；one-shot 角色不沉淀；交叉经验入 project 库带来源标签。验收：委派 lead 后 role scope 目录建成；project 事实带标签。
- [ ] **T7 提炼流水线**：L1/L2/L3 跑通（vendor 机制原样），提炼走配置的模型方案；级联调度正常。验收：多轮对话后 L1 表有原子记忆、scene_blocks 有场景、（低频）persona.md 生成；提炼请求走的是配置的便宜方案。

## 阶段三：会话内压缩与注入

- [x] **T8 会话内分层压缩子系统**（自建，非 vendor）：原文到压缩线（80%）→ 老原文压分层摘要（压缩模型可配）；递归粗化（摘要+记忆到注入上限 20%）；每层摘要持久化；保留线 16%。验收：模拟长会话触发压缩，摘要分层落盘，上下文内历史全程有代表。✅ commit 40f735d，40 单测全绿（含递归粗化诚实边界、保留线不断半条、补召接口、路径穿越防御）
- [ ] **T9 统一注入**：挂 `agent/request`，按四阶段时机模型执行（首轮静态快照 / 前期不注入 / 压缩点切换装最新 / 压缩后 L1 混查）；拼接顺序 team→project→role；预算硬限。验收：四阶段行为逐项举证；压缩前 system 字节级恒定。
- [ ] **T10 工具回查与补召**：查记忆/查原对话注册为 DSH 工具（限 3 次）；补召链路（粗摘要←细摘要←更细←L0）。验收：工具可调用有结果；粗化后能补回细层。
- [ ] **T11 compaction 退役**：官方 compaction 行为被统一机制接管（禁用官方 compaction 行/替换），压缩触发走 T8。验收：--dump-config 官方 compaction 禁用；压缩事件由 memory bundle 产生；官方测试全绿或测试同步修正。

## 阶段四：继承、任务与界面

- [ ] **T12 子对话继承双模式**：继承（默认）——主对话摘要作公共记忆注入子对话、主对话压缩点同步刷新；非继承（角色级可选）；与 memory 字段正交。验收：子对话上下文含公共段且跨子对话字节一致；主对话压缩后活着的子对话公共段刷新。
- [x] **T13 任务实体**：任务表（标题/目标/状态/负责角色），永挂主对话；两入口（界面+主代理工具）；委派/会话挂任务；记忆过滤维度。验收：建任务→委派挂→按任务过滤记忆有结果。✅ commit 8e21c5b，38 单测全绿（SQLite 存储、/memory-task wire、create_task 工具、完成降权做进查询接口）
- [ ] **T14 管理界面**：设置页「记忆」区块（client inject + wire `/memory`）：三维资产分组、查看、删除、绑定角色、提炼状态、任务列表。验收：界面逐项可操作。
- [ ] **T15 配置**：settings 命名空间全配置项（开关/提炼方案/压缩模型/三独立比例 20%-80%-16%/各阈值）。验收：改配置生效。

## 阶段五：验收

- [ ] **T16 不降级验收对照**：§9 每机制"原版代码位置 ↔ 本仓对应物 ↔ 跑通证据"对照表交付。
- [ ] **T17 缓存实测**：连续两次派遣 lead，第二次前缀缓存命中 >0；注入内容动态字段扫描（时间戳/会话 ID 零混入）；导航条目冻结验证。
